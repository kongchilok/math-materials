# 融合班 SOIL Teaching Deck Workflow

SOIL 六顆引擎的骨架不變：先想清楚教什麼，再安排怎麼教，最後才處理怎麼呈現。
本技能在每顆引擎加一層「▶ 融合層」——同一份簡報，讓程度落差很大的班級都學得到。

**兩份必讀資料：**

1. **每次執行前先讀** [references/inclusive-deck-checklist.md](references/inclusive-deck-checklist.md)（簡報設計濃縮檢核表）
2. **按需深讀**五份完整筆記（`G:\我的雲端硬碟\2ndBrain\每日筆記\`）——使用者提到特定障別或個案時，讀對應章節：

| 情況 | 讀哪份筆記、哪一節 |
|-----|------------------|
| 提到讀寫障礙／SpLD 學生 | ②九節總整理 1.3–1.7 |
| 提到 ADHD／坐不住／不專心 | ②九節總整理 2.2、2.6–2.7 |
| 提到自閉症／ASD／固執行為 | ②九節總整理 7.2–7.4 |
| 提到臨界智能／學得慢 | ②九節總整理 3.3–3.4；③數學彙整 4.5 |
| 提到聽障／視障 | ②九節總整理 4A/4B |
| 提到資優但有障礙（2E） | ②九節總整理 8 |
| 要設計分層任務／練習 | ③數學彙整 3、①策略手冊 1.4 |
| 概念呈現卡關、要 CRA 細節 | ①策略手冊 2.1–2.3 |
| 簡報目標要對接 IEP | ⑤IEP第8-9點填寫指引 |

> 雲端環境讀不到 G:\ 時，以內建檢核表為準，不要中斷流程。

## 第一步：判斷工作模式

收到請求後，不要直接開始做。先問一題判斷模式：

> 請問你目前的狀況是？
> 1. 我有素材（文字、教材、文件），想做成融合班教學簡報
> 2. 我有現成簡報（.pptx），想改成融合生跟得上的版本（或診斷融合友善度）
> 3. 我只有一個主題，想從頭開始
> 4. 我想定義一套融合簡報風格（YAML）給之後反覆使用

| 回答 | 工作模式 | 跑哪幾顆引擎 |
|-----|---------|------------|
| 1 | 全流程模式 | 引擎 1→2→3→4→5→6 |
| 2 | 診斷修改模式 | 引擎 4（+3 補頁面角色）＋融合友善度診斷 → 修改 .pptx |
| 3 | 全流程模式 | 先協助蒐集資料 → 引擎 1→2→3→4→5→6 |
| 4 | 風格定義模式 | 引擎 5 |

使用者請求已非常明確時（如直接貼教材說「做成融合班簡報」）可跳過此題，直接進全流程，但進引擎一前先補問下方細節。

### 進入引擎一之前，補問（一次問完，不分多輪）：

> 開始前確認三件事：
> 1. **教學對象與時長？**（如：初三、一節課 45 分鐘）
> 2. **這份簡報是全班共融用，還是抽離小組（資源班）用？**
> 3. **班上融合生的情況？**（障別、大約人數；有特別要照顧的個案可簡述，不用姓名）

第 2 題決定 Accommodation／Modification 路線（見檢核表 A 節）；
第 3 題決定融合層要重點套用檢核表 B 節的哪幾列。使用者不清楚障別時，直接套 C 節六類通用策略即可，不要追問診斷細節。

## 引擎一：SOIL 概念定位師

> 目標：抓出教學主軸——這堂課到底要學生帶走什麼

分析素材，產出「概念定位稿」六項：

1. **總概念**：最核心的 1 個概念（一句話）
2. **子概念**：支撐總概念的 3 個子概念
3. **常見誤解**：學生最容易產生的 3 個誤解（各附正確理解）
4. **帶走一句話**：學生最後只能記住一句話，那句是什麼
5. **最小事實包**：支撐理解所需的最少事實
6. **投影片 vs 講稿**：哪些內容上投影片，哪些口頭補充

### ▶ 融合層（概念定位稿加三項）

7. **障礙點分析**：融合生在這個概念上最可能卡住的地方，從四個維度掃描——
   語言負荷（文字題、術語）、工作記憶（多步驟、心算）、抽象度（符號、比喻）、
   程序性（運算順序、格式）。對照檢核表 B 節該班障別列。
8. **分層帶走句**：帶走一句話之外，加一句「保底版」——融合生至少要能說出的更具體、更操作性的版本。
9. **CRA 對應表**（數學／理科概念必做）：這個概念的「具體物是什麼｜表徵圖是什麼｜抽象式是什麼」一行對照。

完成後呈現給使用者確認，再進下一步。

## 引擎二：SOIL 脈絡定位師

> 目標：安排理解節奏，不是排章節

三段理解節奏：

| 節奏 | 功能 | 佔比 |
|-----|------|-----|
| **引起動機** | 讓學生知道這件事跟自己有關 | 15–20% |
| **維持注意** | 幫學生把資料組成關係 | 60–70% |
| **喚起行動** | 理解轉成可說、可判斷、可應用 | 15–20% |

每段說明：教學目的、放入內容、學生理解任務、建議頁數、入口與出口、常見設計錯誤。

### ▶ 融合層（脈絡定位稿加兩項）

- **轉換點規劃**：對照檢核表 G 節——中學生連續專注上限約 20 分鐘，45 分鐘課至少排
  2–3 個轉換點（操作／討論／分層任務／動態休息），在脈絡稿上標明「第 N 頁＝轉換點」。
  純講述不連續超過 3 頁。
- **預告結構**：開場排一頁「今日課堂流程預告頁」；每個轉換點前一頁加預告句（ASD 可預測性）。

完成後呈現給使用者確認節奏，再進下一步。

## 引擎三：SOIL 頁面架構師

> 目標：給每一頁一個任務，不是列大綱

把三段式脈絡拆成具體頁面，每頁是一個「教學單位」。

### 可用頁面角色（原 SOIL 11 種＋融合 5 種）

| 角色 | 用途 |
|-----|------|
| 封面頁 | 標題、副標、講師資訊 |
| **流程預告頁** ◆ | 今日課堂結構一覽（開場必配，ASD 可預測性） |
| 問題引入頁 | 用問題讓學生產生好奇 |
| 迷思澄清頁 | 呈現誤解，翻轉為正確理解 |
| **CRA 三階頁** ◆ | 具體→表徵→抽象（數學概念頁預設結構，可拆 3 頁或同頁三欄，見檢核表 E） |
| 比較頁 | 兩個概念並排對照 |
| 流程頁 | 步驟、順序、時間軸 |
| **步驟卡頁** ◆ | 固定解題／操作步驟，編號、一步一行（如：讀題→找關鍵字→列式→計算→檢查運算→檢查單位） |
| 分類頁 | 多個項目歸類整理 |
| 案例頁 | 具體例子說明抽象概念 |
| 數據頁 | 大數字、統計展示 |
| **視覺鷹架頁** ◆ | 解題模板示範（四格解題：問什麼｜已知｜策略算式｜解答驗算），之後練習沿用同版型 |
| 總結頁 | 收攏重點，帶走一句話＋保底版 |
| **分層任務頁** ◆ | 行動頁融合版：練習 A★☆☆／B★★☆／C★★★ 同頁呈現、自選晉級（見檢核表 F） |
| 行動頁 | 請學生做什麼（討論、反思） |
| 過渡頁 | 章節銜接（極簡一句話；轉換點前兼作預告） |

◆＝融合層新增角色。

### 每頁要指定

頁碼、頁面標題、頁面角色、本頁唯一主重點（只能一個）、建議頁型、理解任務、
與前後頁的銜接、是否關鍵投影片（★）、**幾何圖形需求**、**融合檢核**。

- **幾何圖形需求**：頁面涉及幾何圖時標記 `geometry` 欄位（圖形類型＋要標的頂點／
  邊／角），引擎六會呼叫 **jh-math-geometry 技能**生成後嵌入。
- **融合檢核**（每頁三個快問）：字量會不會超（≤5 行×18 字）？步驟會不會一次給太多？
  有沒有視覺支持（圖／色塊／編號）？

### 自我檢查

- 超過一半頁面同一種角色？→ 頁型單調，調整
- 某頁「唯一主重點」其實含兩個概念？→ 拆頁
- 每頁都有理解任務？→ 沒有的頁可能多餘
- 數學概念頁有沒有走 CRA 序（具體／表徵在抽象之前）？
- 每 10–15 分鐘教學時間內有沒有轉換點？轉換前有沒有預告？
- 有幾何概念但忘了標 geometry？→ 補上

完成後呈現給使用者確認。

## 引擎四：SOIL 認知編修師

> 目標：用六個認知詞＋融合檢核把每頁修成真正的教學頁

### 六個認知詞（SOIL 原裝）

| 認知詞 | 做什麼 | 怎麼判斷 |
|-------|-------|---------|
| **降雜訊** | 刪掉無助理解的元素 | 拿掉後理解會變差嗎？不會就刪 |
| **區塊化** | 同類資訊歸在一起 | 一眼看得出這頁有幾個群組嗎？ |
| **增資訊** | 補上理解的橋梁 | 概念間的關係標記夠清楚嗎？ |
| **結構化** | 讓主從關係可見 | 看得出主概念與子概念嗎？ |
| **順脈絡** | 排出合理閱讀順序 | 視線會自然照你希望的順序走嗎？ |
| **步驟化** | 讓理解一步一步跟 | 動態呈現該分幾步出現？ |

### ▶ 融合層：第七檢核「融合友善」

逐頁再過一次檢核表 B／D 節，特別盯：

- **讀寫障礙八困難逐項避開**（②筆記 1.4）：數字符號間距（6/9、＋/× 易混）、
  運算順序有提示、直式對齊有格線、文字題用詞精簡、關鍵字加粗
- **一次一指令**：指令頁不出現複合指令（「先看例題然後做練習並檢查」→ 拆三步）
- **正面淺白用字**：說「要做什麼」，不說「不要做什麼」
- **比喻有解釋**：用了比喻的頁面，下一行就給白話對應（ASD 按字面理解）
- **抽象頁留視覺線索**：符號算式頁角落保留表徵縮圖

全流程模式：在引擎三頁面表完成後逐頁預規劃。
診斷修改模式：見文末「診斷修改模式」。

### 認知編修報告格式

```
### 第 N 頁：[頁面標題]
- 降雜訊／區塊化／增資訊／結構化／順脈絡／步驟化：[各一句具體建議]
- 融合友善：[對照檢核表 B/D 的具體問題與改法]
- 修改優先級：高 / 中 / 低
```

## 引擎五：SOIL 風格建構師

> 目標：把風格固定成規則，讓整份簡報一致

只有教學骨架（引擎 1–4）確定後才進風格層。

### ▶ 融合層：硬規則先行（不可被風格偏好覆蓋）

**檢核表 D 節是硬規則**，任何風格偏好都要在它之上疊加：
無襯線黑體（微軟正黑體／思源黑體）、內文 ≥ 20pt、標題 ≥ 32pt、行距 1.3–1.5、
每頁 ≤ 5 行 × 18 字、淺色底非純白、左對齊、難度只用星星、強調用加粗＋色塊
（不用底線斜體）、色盲安全配色、版型高度一致（ASD 可預測性）。

### 使用者有參考簡報／圖片時

做風格逆向工程（氣質、標題位置、配色、留白、強調方式、頁型偏好、圖像風格），
但與硬規則衝突處一律以硬規則為準，並向使用者說明改了什麼、為什麼。

### 使用者沒有偏好時

| 教學場景 | 建議配色方向 | 氣質 |
|---------|------------|------|
| 初中共融全班 | Teal Trust（青藍主色）高對比版 | 活潑、清楚 |
| 抽離小組 | Sage Calm（灰綠）低刺激版 | 溫和、安定 |
| 教師研習（融合教育主題） | Warm Terracotta | 溫暖、專業 |

配色選定後用色盲模擬思維自查：語意不靠紅綠對比、不靠顏色深淺區分層次。

### 風格規則（通用）

標題位置一致、章節色一致、同類頁型結構一致、每頁都有視覺元素（不做純文字頁）、
不在標題下加裝飾底線、風格服務理解不炫技。

### 輸出

風格設定摘要：配色 HEX（主／輔／強調）、字型、標題與內文字級、行距、佈局偏好、
（若抽離版）低刺激調整說明。引擎六直接套用。

## 引擎六：SOIL 簡報總導演

> 目標：整合前五顆引擎結果，生成 .pptx

### 第一輪：生骨架

整合概念定位稿（含融合三項）、脈絡定位稿（含轉換點）、頁面角色表（含融合角色與
融合檢核）、認知編修指引、風格設定（含硬規則）。

**技術執行（本機 Windows 環境）：**

1. **幾何圖先行**：頁面表有任何 `geometry` 標記時，先呼叫 **jh-math-geometry 技能**
   逐一生成 PNG，親眼檢視每張圖（標籤、角弧、記號正確）後才進入簡報生成。
   不要先生骨架再補圖。
2. **生成 .pptx**：呼叫 **pptx 技能**（anthropic-skills:pptx）取得本環境的生成方法與
   技術規範（PptxGenJS 或 python-pptx），遵循其全部規範：16:9、0.5" 邊距、
   深色封面＋結語、淺色內容頁。字級以本技能硬規則為準（內文 ≥ 20pt，
   高於 pptx 技能預設的 14–16pt）。
3. 數學式必須正確呈現（分數、根號、次方），不可用純文字硬湊；圖形以 PNG 嵌入。

**頁面角色 → 佈局對照（融合新增角色）：**

| 頁面角色 | 建議佈局 |
|---------|---------|
| 流程預告頁 | 直式時間軸／編號清單，圖示＋短語 |
| CRA 三階頁 | 三欄並列（具體｜表徵｜抽象）＋對應箭頭；或連續 3 頁各一階 |
| 步驟卡頁 | 直式編號大卡，一步一行，行距加大 |
| 視覺鷹架頁 | 2×2 四格（問什麼｜已知｜策略算式｜解答驗算） |
| 分層任務頁 | 三欄同版面：A★☆☆｜B★★☆｜C★★★，附晉級提示 |

其餘角色沿用 SOIL 原對照（封面深色全版、迷思澄清雙欄 ❌/✅、比較雙欄、
流程橫向箭頭、分類網格、數據大數字、總結條列＋帶走句、行動深色、過渡全版色塊）。

### 第二輪：修頁面（視覺 QA）

1. 用 **office-pdf-convert 技能**把 .pptx 轉 PDF（本機已實測的轉換梯級，勿手寫 COM）
2. 逐頁 Read PDF 檢查：元素重疊、文字溢出、間距、對比、頁面角色是否一眼可辨、
   幾何圖對齊與比例
3. 有問題就修，重新生成再檢

### 第三輪：最終檢查

SOIL 清單：
- [ ] 每頁只有一個主重點
- [ ] 三段式完整（動機→注意→行動）
- [ ] 頁面角色多元
- [ ] 關鍵投影片有突顯
- [ ] 帶走一句話在總結頁（含保底版）
- [ ] 常見誤解有被處理
- [ ] 風格一致、無純文字頁
- [ ] geometry 頁的圖形已預覽確認、對齊正確

融合清單：**逐項跑檢核表 H 節**（字量／字級／CRA 序／步驟卡／轉換點／預告頁／

## 診斷修改模式（使用者帶現有 .pptx 進來）

1. **讀取**：提取文字內容＋轉圖檢視版面（工具鏈同引擎六）
2. **引擎四診斷**：六認知詞逐頁檢查
3. **融合友善度診斷**：逐頁對照檢核表 D 節硬規則＋B 節該班障別列，輸出對照表——
   「現況 → 問題（影響哪類學生）→ 改法」
4. **補頁診斷**：缺不缺流程預告頁、步驟卡頁、分層任務頁？轉換點夠不夠密？
5. **輸出認知編修報告**（含融合友善欄），標優先級
6. **使用者確認後才動手修改**；修改後重跑第二、三輪 QA

## 核心原則（貫穿所有模式）

SOIL 六原則照舊：教學簡報≠商業簡報、從學生接收順序設計、一頁一重點、
頁面是教學單位、風格服務理解、先教學判斷後工具操作。

融合層四原則：

1. **同一份、不標籤**：預設全班同一份簡報，分層靠學生自選，不做「特殊版」點名個案
2. **調整 vs 剪裁要標示**：Accommodation／Modification 路線在產出時說清楚，方便對接 IEP
3. **鷹架要能撤**：步驟卡、視覺鷹架是過渡工具，設計時想好之後怎麼淡出（fade out）
4. **Asset-based 用語**：簡報內外都不用「補救、落後、跟不上」等 deficit 標籤
